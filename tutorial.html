Tutorial

Your first scenario

A small, complete example: three screens, a couple of clickable actions, and one scenario that ties them together. It assumes you've already installed Screen Macro and have your game running.

The example uses generic screen and button names — swap in your own game's actual screens as you go. Everything below is written for Desktop mode; Android mode works exactly the same way, except every capture pulls a screenshot from your configured LDPlayer instance instead of your physical screen.

A scenario will send the bot to Farm, click collect, then to Shop, click buy — repeating on a cooldown.

1

Create three screens

In the Screen Editor tab.

The Home screen

  1. Click + Add, type Home, press OK. If this is the very first screen in a brand-new config, you'll first be asked whether this config targets Desktop or Android. Android additionally walks you through a short LDPlayer setup wizard before continuing.
  2. With Home selected, the Flow Actions table shows a screen_marker row. Select it and click Recapture:
    • Step 1/2 — drag a box around a small, unique part of the Home screen that's always visible (a logo or title works well).
    • Step 2/2 — drag a slightly larger box around where that marker should be searched for, or press Escape to auto-pad around it.
  3. Click Set as Home so the bot knows this is its home base — the screen it falls back to for recovery.

The Farm screen

  1. Click + Add, type Farm.
  2. Capture its marker the same way as Home, using something only visible on the Farm screen.
  3. Click + Back and pick how the game actually leaves this screen — an image button, a fixed click point, or a key press (e.g. Esc). Every screen except Home needs one of these.
  4. Click + Click Image, drag a box around the button that collects resources, and name it collect. Nothing else to configure for a simple click — it stays on the Farm screen after firing.

The Shop screen

Repeat the same pattern:

  1. + Add → Shop.
  2. Capture its marker.
  3. + Back to get back out of the Shop screen.
  4. + Click Image around the "buy" button, name it buy.

Wire up navigation between them

  1. Select Home in the list.
  2. Click + Navigate, drag a box around whatever button on Home opens the Farm screen, name it go_farm, and choose Farm as the destination when prompted.
  3. Still on Home, click + Navigate again for the button that opens the Shop screen, name it go_shop, destination Shop.

At this point: Home can reach Farm and Shop; Farm and Shop can each get back to Home via their Back action; Farm has a collect action and Shop has a buy action. That's enough for the navigator to path between any of the three screens automatically.

2

Build the scenario

In the Scenario Editor tab.

  1. Click + Add — a new scenario is created and selected.
  2. Fill in the form:
    • Name: farm_and_shop
    • Enabled: checked
    • Cooldown seconds: how long to wait after this scenario finishes before it can run again (default 5 is fine to start with)
  3. Click + Add Step:
    • Navigate to: Farm
    • Actions: check collect
  4. Click + Add Step again:
    • Navigate to: Shop
    • Actions: check buy
  5. Click Save.

There's no "start from" field to set — each step's own navigation already computes the shortest path from wherever the bot currently is, so this scenario is eligible to run from Home, Farm, Shop, or anywhere reachable from them.

3

Run it

  1. Switch to the Start tab.
  2. Click Start.

The bot detects the current screen, paths to Farm, clicks collect, paths to Shop, clicks buy, then waits out the cooldown before doing it again.

Where to go from here

Check actions

+ Check detects an image without clicking it — useful for prerequisites (e.g. "only run this scenario if a resource icon is full").

Alternates

On a flow step, watch for an unexpected popup (like an ad) mid-step and react to it without aborting the whole scenario.

Depends on

On an individual action's checkbox, makes it wait for another action in the same step to have already fired first.

Configs

The Configs tab saves this whole setup — screens, scenarios, and templates — as a named config you can reload, back up, or share.
